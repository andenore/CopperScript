# Four-switch buck-boost EMI support: implementation and validation

Status: joint passive extraction implemented with numerical repairs and explicit full-wave fixtures, 2026-11-23. The frozen lightgun network passes the existing finest-pair matrix criteria at 1/10 MHz; 100 MHz remains indicative, and its full-wave model remains unqualified by geometry/resource limits. This update supersedes the historical P1a/P2a/P2b status entries below. Generic implementation belongs in CopperScript; reusable manufacturer facts belong in CopperLib; operating conditions and qualification evidence belong in the consumer. No consumer source, compiler/library pin or board geometry was changed. This record does not claim EMC compliance.

### Numerical repair and frozen-state replay

The coupled FDTD passivity failure was a spatial port-measurement mismatch. The pinned `ems 0.0.5` implementation distributes a lumped element over transverse columns and records their terminal current (`src/engine/lumped.rs`, terminal-current definition); its default voltage probe follows only the centre line (`src/port/mod.rs`, `LumpedPort::add_to`). `copper-fullwave::solve` now supports averaging voltage over those same columns. Only the external adapter enables it, so buck's convention is unchanged. Longer decay alone did not remove the original failure. With averaged voltage, the compact 1–3 GHz two-port fixture passes the unchanged reciprocity, full Hermitian passivity and two-mesh limits, using 0.3/0.2 mm meshes. The external adapter also requires −80 dB recorded decay and disables independent tail extrapolations. This is qualification of the stated fixture envelope, not arbitrary packages.

`RegionSpec.raised_bridges`, `PortSpec.elevation_nm` and rectangular PEC posts replace obstructing flat fixtures only when heights are explicitly supplied. CLI options are `--fullwave-capacitor-height MM` and `--fullwave-source-height MM`; scopes report both heights and the voltage convention. Native copper underneath is retained. These fixtures include their own fields and exclude real component/package constitutive models. No height is inferred from TPS63020 or capacitor metadata. Source-volume collisions, obstructed in-plane gaps, discretized short/shared source edges and different-net mesh merging prevent qualified results. General non-facing raised sources remain unsupported.

The saved lightgun replay is now a genuine opt-in Rust regression, `crates/copper/tests/emi_saved_network.rs`, requiring explicit state/report paths and SHA-256 values. Its state digest remains `7265ff2c6e48e7e064ffece905d510226a60d616194a22ee0ddd7f8183778e0d`; the matched earlier report `target/emi-joint-lightgun-final.json` has digest `b6c9e46a16ab777a01836758aba431d7262fadec459a3bdd2c16ec3631169c88`. **This is frozen-artifact replay, not current-source validation:** the live CopperLib changed after that review, and a new locked source invocation failed `PKG008` (expected content digest `56ec5bd80a44494f9cb9235eaee1db8e5c7f8f41d707062c2204ee633ae50869`, observed `1ab94fde5ffb0342db435fb01e0b2dca4df5d4629cf025554c8d269a27bb08d9`). The lock was not modified or bypassed.

The initial 16,000-filament-budget replay resolved native connectivity but remained indicative because the finest/next filament ratio was only 1.06. An intermediate 20,000-budget study produced 16,775, 14,009 and 13,477 filaments with no topology mismatches or unresolved gaps, but the resistance transfer between contacts `4→15` and `5→15` changed by 9.1% at 100 MHz, above the unchanged 5% diagonal-normalized limit. That study did **not** establish convergence.

The external adapter protects native loop-net tracks from budget coarsening, requests four/three/two cells across narrow copper in the default three-mesh series, and uses pitch ratios 1:2:4. Both width resolution and local defect repair can request 25 µm cells without changing the partition floor or contact tolerance; buck retains its earlier width, pitch and 50 µm conventions. A separate 60 µm slot regression verifies that the finer repair resolves both copper islands without connecting them. An intermediate 26,000-budget geometric preflight, still using the old 50 µm width floor, produced 25,894, 21,067 and 16,631 filaments with matching connectivity and no unresolved gaps. This preflight alone does not qualify the matrix.

The completed 100 MHz study of that 4/3/2 series is still **indicative**: output contact `11→15` resistance changes by 6.2%, above 5%. It completed in 944.59 s; the finest mesh had 11,701 loop equations, with 81.9 s assembly and 481.4 s frequency solving. The other two meshes also had no topology mismatches or unresolved gaps. This result is recorded in `target/emi-repair-compact-memory-100mhz.log`; the opt-in acceptance assertion correctly fails. Connectivity and lower memory use do not establish electrical convergence.

A nominal 5/4/3 series with the same old 50 µm width floor returned `ok` in 1,964.20 s (`target/emi-repair-five-width-100mhz.log`), but this is **not accepted as evidence of resolved narrow-trace currents**. The floor can clip both four and five requests to the same transverse resolution. The new independent geometry regression `width_refinement_really_subdivides_a_narrow_current_path` demonstrates this on a 200 µm conductor, verifies conserved cross-section, and proves that the 25 µm width-request floor produces an actual subdivision. `MeshSpec.loop_cell_nm` is separate from the defect floor and reported as `loop_cell_floor_mm`. Current qualification must use that explicit width floor rather than counting nominal width requests alone.

Dense-system memory is reduced in `copper-extract::network`: assembly writes directly into the final symmetric matrix, eliminating the intermediate upper triangle (about 2.7 GB at 26,000 branches). The solver forms each row of the complete `B L B^T` using one temporary branch-length row per worker, avoiding the whole `B L` intermediate (another approximately 4 GB for this 32,137-branch case). It then retains only the original inductance rows needed by port paths before frequency factorization. Summation order and every matrix entry are unchanged. The saved-study timings above precede the row-streaming storage change and are not its performance benchmark. All native branches, floating-metal loops and their mutual coupling remain in the equations; this is storage reduction, not a physical approximation. `extract_hot_loop_with_progress` exposes meshing, assembly and frequency-completion diagnostics without treating intermediate matrices as qualified results. The original extraction entry point remains compatible. Dense assembly and factorization still impose substantial memory and time costs. The explicit CLI ceiling is raised from 20,000 to 32,768 filaments so larger native networks can be studied; the default stays 9,000. Help and range errors identify the memory cost (about 8.6 GB for the 32,768-branch inductance matrix alone, before workspace). A larger accepted budget is not a convergence or memory-availability guarantee.

The full-wave numerical references include a symmetric coupled native-copper network (two meshes, all columns), an asymmetric raised-capacitor/elevated-source network (passivity and reciprocity, explicitly single-mesh), and the existing independent microstrip benchmark with distributed voltage enabled. The latter gives 51.389 Ω against the analytic 49.400 Ω reference, within its existing 5% limit. No matrix is projected onto a passive or reciprocal approximation. Local logs are `target/emi-fullwave-final-reference.log`, `target/emi-raised-asymmetric-reference.log` and `target/emi-voltage-independent-reference-final.log`.

With explicitly assumed 0.5 mm capacitor and controller fixture heights, all four lightgun FDTD ports construct successfully. The standard model has 4,817,792 cells and estimates approximately 27,594 seconds **per column**, before a second mesh. It also reports different-net mesh-line merging. A normal bounded review therefore cannot yield a qualified lightgun full-wave matrix; larger budgets alone do not resolve the geometric qualification flag. Fixture heights, final stackup and package/component models still require manufacturer evidence or measurements. No hours-long full-board solve was launched.

### Mesh controls and reproducible replay

`--extract-width-cells N` accepts 4–16 when `--extract` is selected. It controls the finest requested transverse subdivision; the external coarser meshes request `ceil(N/1.5)` and `ceil(N/2.25)`. Defaults remain four for external networks and two for buck. The new control changes resolution, not conductor dimensions or port physics. Reports include requested width cells and both minimum cell sizes; a request is not proof that every geometric feature was subdivided.

The current frozen-artifact study uses `--extract-budget 32500 --extract-width-cells 5 --extract-ideal-capacitors --extract-margin 1`, the external adapter's 25 µm loop/defect floors and a 1 mm extraction margin. Its geometric preflight yields 32,137 / 26,025 / 21,420 filaments, zero topology mismatches and zero unresolved gaps on all three meshes (`target/emi-repair-real-width-five-32500-preflight.log`).

The completed 100 MHz study remains **indicative**: the self-resistance at contact `5→15` changes from 0.0156000602 Ω on the next mesh to 0.0164289506 Ω on the finest, a **5.0453036%** change above the unchanged 5% limit. All inductance entries pass their 3% limit; no other status reason is reported. The finest pair each reports 21 copper components, whereas the coarsest reports 20: the earlier step is not comparable, so this study does not establish contraction across all three levels or a discretization error bound. The run took 2,254.78 s (`target/emi-repair-real-width-100mhz.log`). This profile is not qualified at 100 MHz. Diagnostics now retain three decimals so the failure does not appear to equal the threshold after rounding.

A six-cell request at the maximum 32,768 budget leaves four topology mismatches and ten unresolved gaps (`target/emi-repair-real-width-six-preflight.log`); no numerical solve was launched for that invalid mesh. Increasing nominal resolution within the existing budget is therefore not a demonstrated remedy.

The separate **1/10 MHz study passed** the existing full-matrix L/R and finest-pair comparability criteria with `status=ok` and no status reasons (4,676.16 s; `target/emi-repair-real-width-1-10mhz.log`). ### Joint-network implementation

`ExternalNetwork` in `copper-drc::emi::loop_model` validates and merges the two contours, selected capacitors, physical contact identities and all native legs. Each rail port uses its own loop's selected return; additional return-contact ports link to the primary reference. This independent tree basis preserves the voltage and current at different physical returns without a package short. `HotLoopInput.external_peer` supplies this contract to both adapters. No converter is relabelled as buck.

`copper-extract::board` retains neighbouring and floating native copper, checks physical connectivity and net overlaps, and assembles independent contact ports and capacitor boundaries. It explicitly refuses source blind/buried vias, whose layer spans the current CAM reader does not retain; it never silently extends them through the stack. The default coplanar capacitor fixture rejects overlap with native copper and names its location. `--extract-ideal-capacitors` is an explicit PEEC-only alternative: ideal terminal shorts with no capacitor body conductor or its magnetic field. It is PCB-only extraction, not a mounted-capacitor model. `emi_check.rs`, `emi_extract.rs` and CLI help define and validate the option; report scope records it even if the solve fails.

`copper-extract::hotloop` retains per-column current/via observations and selects the correct diagonal and current map for each reported loop. `emi_extract.rs` solves one joint network per controller and reuses it for both loop identities. `external_joint_contact_network/v1` carries signed ports, both selected capacitors, other open components and the actual reported port. R/L matrices include shared-return and mutual coupling. Neither a package model nor equal contact-current sharing is introduced. Existing buck behavior is preserved.

The new `copper-extract::fullwave` adapter uses validated native geometry, contained rectangular contact patches and explicit source-gap fields. It refuses automatic package straps and colliding capacitor fixtures. `emi_fullwave.rs` caches one all-column result per controller and reports it separately as `fullwave_external`. The allowance is shared across columns and meshes; abort diagnostics retain the completed-column count and never expose an incomplete matrix as usable. Results include frequency-indexed complex Z, port names, source rectangles, run statistics, approximations, full-matrix refinement and explicit failure reasons. Acceptance checks include 1% normalized reciprocity and a 1 ppm shifted Cholesky test of the normalized Hermitian part for every complex current combination. A single mesh or over-5% matrix refinement difference remains indicative. The full-wave source gap and PEEC excluded gap are different boundaries, so no automatic cross-method agreement is claimed.

The earlier coarse integration matrix failed passivity; that failure is superseded by the voltage-measurement repair and two-mesh validation above. General arbitrary-contact source geometry and manufacturer capacitor/package fixtures still need independent qualification. They are not silently accepted.

Four-switch current-driven radiation and ringing now decline with `scenario=uncharacterized` until a bound waveform exists. The legacy `current_peak` value is retained only as unqualified limit metadata. For TPS63020, the datasheet's 4 A typical average switch-current limit cannot establish an instantaneous commutation peak. Passive extraction does not require that missing information. Actual excitation/emissions prediction still needs characterized operating points, modes/timing and phase-resolved contact currents, component/package/source/load/harness models and measurement correlation; P5 below remains a separate extension, not an implied output of this implementation.

Independent tests cover both the weak-coupling mirrored pair and a common-return pair. The latter checks analytic shared-path resistance, all L entries against independent raster/field energy within 5% diagonal-normalized error, substantial signed mutual coupling, and reversal of one port (unchanged self terms, reversed transfer signs). The ideal-capacitor test checks the PCB-only path's analytic resistance within 2% and proves no body conductor was inserted beneath obstructing native copper. Floating-metal and overlap cases, repeated thermal-pad primitives, malformed identity and legacy buck cases remain covered.

### Historical implementation progress


**P2b — independent controller-contact network (2026-11-23).** The paired-contact metadata refusal is replaced by an N-1 port basis over controller rail and power-return contact identities. The selected return contact is the voltage/current reference; every other contact, including additional returns, has its own port. A reference choice introduces no conductor or equal-voltage constraint between package pins. Each contact is a whole-pad equipotential patch, reused consistently across ports: an explicit boundary assumption excluding package spreading/contact impedance. The selected capacitor still receives its explicit copper fixture. Every contact must connect to its own capacitor side through native filled copper before the fixture is added. Capacitor groups with more than one contact identity, disconnected same-number lands, through-hole contacts and mixed contact layers remain unsupported. The single-contact facing-patch model and all buck conventions are preserved.

The managed TPS63020 footprint represents pad 15 as a central land and eight overlapping edge shapes. Repeated numbers therefore carry an explicit occurrence count, validated against the exported copper. They become one contact only after their same-net, same-layer polygon union is proven continuous. Two separate lands with the same number are refused even when an external trace connects them. DRC contact discovery ignores non-electrical apertures, and the extractor checks only actual copper when identifying contacts or unassigned pads. The paired fixture includes overlapping return primitives and non-electrical paste apertures, plus a disconnected-land refusal case. No footprint or library was changed.

The contract lives in `copper-drc::emi::loop_model::ExternalContour` (`groups`, `validate`, `contacts`, `contact_ports`); PEEC input validation remains in `copper-fullwave::hotloop::HotLoopInput::peec_port_layout`. `copper-extract::board::{loop_ports,build_layout}` builds the separate contacts and checks every rail/return leg. The existing multiport network, convergence and independent reference solvers supply all matrix entries without changes to their numerical algorithms. `emi_extract.rs` exports the resistance matrix alongside L and records the scalar boundary; `emi_current.rs` and `copper-report::emi_current` label the excitation in current maps. No public source syntax or new CLI flag is required.

`extract_scope.model = external_contact_network/v1` includes signed `ports` in matrix order and explicitly leaves contact-current sharing unspecified. Per-column unit currents satisfy `V = Z I`; the reference contact carries minus their sum. The complete balanced-current basis can later be connected to an explicitly supplied package/source model. It is **not** an equal-potential reduction of all supply pins or an assumed equal current split. Scalars, via shares and current maps remain port 0 responses with every other port current zero, and say so. R/L are external PCB-plus-capacitor-fixture quantities, not complete commutation-loop values. Coupling between these contact ports is evaluated; coupling between the separately extracted input/output networks is not. No conducted-emissions substitution is enabled.

At most 16 contact ports are accepted before board export/fill, independently of the existing filament budget. Assembly is shared across columns; the added cost is more right-hand-side solves, matrices and reference columns. Mesh and independent-reference qualification continue to cover all R/L entries and frequencies. No existing tolerance is relaxed. The new fixture has two rail and two return contacts, branched by known 10/12 mm copper paths. Its three-port resistance matrix is checked against shared tree-path lengths (3%), its entire inductance matrix against independent raster/field energy (10% normalized to the geometric mean of diagonal entries), and both matrices for reciprocity and positive definiteness. A differential rail-pin excitation must retain the resistance of both branches; removing either added connection must fail. Reordered metadata must preserve the basis, and over-budget networks must refuse before extraction.

The device motivation is confirmed by [TI TPS63020 datasheet revision I, pin functions](https://www.ti.com/lit/ds/symlink/tps63020.pdf): separate VIN and VOUT contacts and a power-ground thermal pad. These facts do not provide a package parasitic network or contact-current waveform. The typical 4 A average switch-current limit remains unsuitable as a guaranteed instantaneous peak; this passive model does not consume it. CopperLib and the lightgun design/pins are unchanged by P2b.

## 1. Decision and scope

Implement a typed, topology-aware commutation-loop contract shared by geometric screening, PEEC and full-wave adapters. Deliver passive input/output interconnect extraction first, independently of converter excitation. Then add a joint multiport model and explicit waveform scenarios. Do not remove the existing guards until their replacement validates the topology, terminal identities, closures and supported analysis scope. Never relabel a four-switch converter as a buck.

Initial coverage is a non-isolated, non-inverting, single-inductor four-switch stage with recognized rail, switch and return terminals. Other buck-boost families, external gate-drive loops, package-internal coupling, multiphase stages and arbitrary magnetic networks remain separately unsupported unless explicitly modeled. A `buck_boost` category alone does not prove this structure.

The useful first release answers “what passive impedance does this explicitly defined board loop present?” It does not answer “what current flows in the converter?” or “what will a compliance receiver measure?”

## 3. Physical model and terminal contract

TI identifies the input commutation loop as active during buck cycles and the output commutation loop during boost cycles; it distinguishes these from gate-drive loops. Use this topology, not the whole energy-transfer path through the inductor, as the initial high-di/dt loop basis. [TI SSZTAE3, Figure 1](https://www.ti.com/lit/ta/ssztae3/ssztae3.pdf).

Use neutral switch names: QIH/QIL are the input high/low devices, QOH/QOL the output high/low devices; SW1 and SW2 are the inductor ends. Proposed loop orientations:

| Loop | Differential commutation contour | Single-loop extraction convention |
| --- | --- | --- |
| Input | CIN+ → VIN → QIH → SW1 → QIL → PGND → CIN− → CIN+ | Port positive at VIN, negative at SW1; explicit ideal QIL closure SW1–PGND and CIN closure. |
| Output | COUT+ → VOUT → QOH → SW2 → QOL → PGND → COUT− → COUT+ | Port positive at VOUT, negative at SW2; explicit ideal QOL closure SW2–PGND and COUT closure. |

These closures define passive extraction fixtures. They are not simultaneous transistor on-states, a converter operating simulation, or a model of die/bond-wire geometry. The orientation is a mathematical convention; waveform projection must respect its sign. Derive commutation excitation from the difference between adjacent circuit states so continuous inductor paths cancel where appropriate. Maintain separate voltage-driven SW1/SW2 coupling observables; loop inductance alone does not cover their electric-field coupling.

For an integrated device, also support a clearly labeled **external rail-to-PGND contour** without guessing a switch path inside the package. It exposes only the PCB interconnect. Never silently fall back from a switch-referenced port to this contour: they have different boundaries and synthetic path bias. Require the same convention for numerical comparisons and external package additions. Do not subtract an estimated strap inductance as if it were calibrated de-embedding.

Proposed typed contract, implemented initially in a new `crates/copper-drc/src/emi/loop_model.rs` and exported through `emi.rs` (both solver crates already depend on DRC):

- `LoopId { controller, kind }`, where kind is stable `standard`, `input`, or `output`; a separate scenario ID and capacitor/port ID. Display names never act as keys.
- `CommutationLoop`: topology family, ordered logical terminals, physical pad/contact sets, supply/return/switch nets, primary capacitor and all candidate branches, return domain, orientation and provenance.
- `LoopExtractionSpec`: selected reference planes, actual copper legs, explicit component closures, omitted components, port convention, terminal patches, ROI and fill/stackup bindings. One builder feeds both numerical adapters.
- `TerminalGroup`: all physically relevant contacts for paired VIN/VOUT/L1/L2 pins and the PGND exposed/comb pads. Preserve current sharing and per-contact connectivity. Never join equal net names across a gap, merge whole pads into an equipotential shortcut, or invent a permanent package connection.
- `AnalysisIdentity`: geometry/stackup/fill hash, contract/model version, loop IDs, port order/signs, closures, frequency grid, solver/options and, only for driven results, excitation/operating-point hashes.

Use structured endpoints already available in the language/physical model. Keep a tested legacy finding adapter for buck; new numerical support must not depend on parsing `pad_sequence` prose or choosing the nearest of two switch nodes. Discovery may expose candidate geometry from existing data, but ambiguity blocks the switch-referenced numerical model.

For TPS63020, bind VIN 10/11, L1 8/9, L2 6/7, VOUT 4/5 and PGND 15 explicitly from the part contract. Signal ground pin 2 is not a substitute for the power return. The current board's named nets and inductor endpoints permit a provisional structural mapping; a reusable explicit part mapping is the preferred supported path. Do not hide the output-pin name heuristic's provenance.

Both adapters must use native filled copper, actual antipads/slots/thermals, layer heights, via contacts and every branch retained in the ROI. Check topology before and after meshing. In routed analysis, missing closure is an error/partial result, not permission to draw straight copper. Keep existing placed-buck synthesis behavior for compatibility, with its approximation labels; a new four-switch synthesis mode would require explicit opt-in and must not claim routed extraction.

## 4. Coupling and passive-versus-driven results

First implement isolated per-loop L/R/Z with the other loop's boundary condition stated. This is useful partial coverage; it must say `inter_loop_coupling: not_evaluated`.

Then build one union ROI containing both loops, shared returns and relevant capacitor branches. Assemble a joint port network from the common terminal contract. Keep component terminals as ports when their impedances will be attached externally; do not simultaneously short a capacitor and add its RLC model. The initial shorted-capacitor contour and the assembled converter network are separate model configurations.

Define passive impedance as `V_i(f) = Σ Z_ij(f) I_j(f)`, with currents positive into the declared positive terminals and non-driven ports open for Z parameters. Full-wave S-to-Z conversion must document reference impedances and convert all columns consistently; loaded driving-point V/I is not an open-circuit Z diagonal. Derive port networks by terminating/eliminating the same primitive model, rather than summing separately extracted loop inductances.

Extract signed mutual terms, shared-return resistance/inductance and via-current distributions. Check reciprocity and passive energy, including a positive-semidefinite Hermitian resistive part within numerical tolerance. Low-frequency `L = Im(Z)/ω` is only usable where inductive behavior and the chosen circuit approximation hold. Do not force a frequency-dependent or resonant matrix into the existing single-frequency coupled-L substitution. Report the useful band and residual of any reduced passive model.

Cross-check PEEC and full-wave at common frequency samples and identical terminations/port surfaces. The existing PEEC 1/10/100 MHz and full-wave 30 MHz–1 GHz bands overlap at 100 MHz; use that point when valid, alongside lower-frequency PEEC/reference checks. PEC full-wave resistance must not be treated as copper-loss validation. Mesh agreement is not accuracy; both models can share a wrong bridge definition.

For prediction, combine complex spectra coherently: `V = ZI` and, only if validated field transfer functions exist, `E = Σ H_i I_i`. Unknown relative phase yields a labeled phase envelope or no aggregate prediction, never an arbitrary sum of dB or independent worst cases presented as operation. Include voltage-driven coupling separately. Local FDTD impedance extraction does not by itself compute installed radiation, cable common mode, a LISN voltage, receiver detection or compliance margin.

## 5. Excitation, current metadata and missing data

The TPS63020 datasheet specifies 3.5/4.0/4.5 A minimum/typical/maximum **average** switch-current limit at VIN = VINA = 3.6 V, TA = 25 °C, and a 2.2/2.4/2.6 MHz oscillator range. Its transition controller interleaves buck and boost cycles rather than continuously switching all four devices. PS/SYNC low enables light-load power save. These facts require mode-specific waveforms; they do not specify guaranteed instantaneous current peaks or switching edges. [TPS6302x SLVS916I, §6.5 and §7.4.2–7.4.4](https://www.ti.com/lit/ds/symlink/tps63020.pdf).

CopperLib currently stores 4 A in `current_peak` with a source comment admitting the proxy. Preserve the fact, correct its machine semantics in a future coordinated change: proposed `CurrentLimitSpec` carries average/peak/RMS meaning, min/typ/max, conditions, source locator and whether a bound is actually established. Do not merely rename 4 A to “peak” or replace it with 4.5 A. A typical average limit cannot certify a peak bound; ripple, transients and control behavior remain missing. Unsupported historical values become an explicitly assumed amplitude scenario, without “worst case that bounds operation,” guaranteed margin or current-rating acceptance. Apply this distinction to field, overshoot, energy, conducted, near-field and text/plot paths.

An `ExcitationScenario` must supply:

| Input | Required meaning/evidence |
| --- | --- |
| Operating point | Actual regulator VIN and VOUT, load waveform/mean/range, source and charger state, temperature, component corners, startup versus steady state. Battery voltage is not automatically regulator VIN. |
| Mode | Buck CCM, boost CCM, transition cycle sequence, DCM/pulse skipping/power save, forced PWM or synchronized operation; requested and observed mode distinguished. |
| Timing | Switching frequency or time sequence, duty per active bridge, relative phase, dead time, diode conduction/reverse recovery where relevant, independent voltage and current edge times and ringing. |
| Currents | Inductor average/ripple/peak/valley, capacitor/rail branch currents and signed per-loop commutation currents. Declare reference directions and peak/RMS/complex Fourier convention. |
| Spectrum | Complex harmonics with a common time origin for periodic operation; sample timing, bandwidth, window and acquisition duration for nonperiodic/burst operation. Preserve cross-spectral information where needed. |
| Passive components | Effective L versus current/frequency and DCR; capacitor bias/temperature/age/tolerance, ESR/ESL or impedance curves; package parasitics and switch capacitance versus voltage if used; source, harness and load impedances. |
| Provenance | Measured, validated vendor model, analytic idealization, or assumed sensitivity input; model hash, applicable envelope and uncertainty. Missing is not zero. |

Use analytic ideal CCM fixtures before device prediction. With explicit ideal assumptions, buck has `D = Vout/Vin`, mean inductor current `Iout`, and `ΔIL = (Vin−Vout)D/(L f)`; boost has `D = 1−Vin/Vout`, mean inductor current `Iout/(1−D)`, and `ΔIL = Vin D/(L f)`. Derive rail/capacitor currents by KCL and state timing, not by applying the same 4 A trapezoid to both ports. These are proposed validation derivations, not TPS63020 control models. At zero valley, leave CCM coverage; do not extend its equations through DCM or transition automatically.

The lightgun has 1.5 µH nominal L, 3.3 V output intent and PS/SYNC tied to ground in `src/power.copper`. That last connection makes a fixed-frequency-only regression incomplete. Plan separate cases above, below and near 3.3 V at the regulator input, plus light-load idle and camera/BLE activity and load steps. Exact VIN/load/temperature endpoints must come from the board power envelope and measurement; illustrative 3.0/3.3/4.2 V points may be synthetic tests, not approved board limits. Do not change the PS/SYNC connection to make a model applicable.

Data available now suffices for contract/refactoring work, synthetic truth cases, provisional passive board extraction and clearly labeled sensitivity studies. Research before reusable metadata publication: exact terminal/internal-connection facts, datasheet conditions and waveform/control limitations, EVM reference layout, vendor simulation-model availability/license/supported constructs, capacitor impedance/bias curves, and inductor electrical data. The [TPS63020EVM-487 guide, SLVU365, schematic and Figures 6–8](https://www.ti.com/lit/ug/slvu365/slvu365.pdf) is a reference layout, not an exact model of the lightgun.

Measurements or a validated device model are needed for transition scheduling, burst behavior, current commutation and ringing across the intended envelope. Capture synchronized L1/L2 voltages and inductor/rail currents with documented probe loading and bandwidth; record VIN/VOUT/load/temperature and PS/SYNC. Characterize passive impedance on a fixture with calibrated/de-embedded ports and assembled component models. Later LISN/receiver and installed near/far-field tests must bind cables, enclosure and hardware revision. No new vendor limits or measured results are invented here.

## 8. Independent validation and compute budget

Proposed numerical tolerances below are engineering acceptance targets, not established accuracy. Agree them before implementation and retain actual failures; do not loosen them to make the lightgun pass.

Resource policy:

- Keep numerical work opt-in. Reuse one native fill and cache passive models by complete analysis identity; operating-point sweeps must not remesh unchanged copper.
- PEEC already defaults to 9,000 filaments and caps at 20,000. One dense f64 N² matrix alone costs about 648 MB or 3.2 GB respectively; solver storage is additional. Preflight total memory, not only filament count. Reuse matrix assembly/factorization for multiple right-hand sides where the formulation allows; do not run large dense solves concurrently by default.
- Full-wave runtime grows with cell count × time steps × excited ports × meshes. Report estimated and actual work per loop/port and total. Reuse the region/mesh; preserve decay, withheld-tail, stability and passivity checks for each used response. Do not copy the existing buck-derived 4% sensitivity floor to new geometry as a proven error bound.
- Retain the meaning of existing budget flags. A two-loop request can multiply work under the existing per-loop allowance; explicitly report that scope. Joint-region port columns need a documented shared allowance. If an aggregate memory/time/port cap cannot be expressed by existing options, add one optional total budget in P4 rather than silently changing legacy behavior.
- Provisional CI tiers: structural/report tests without FDTD; small PEEC cases under a 2,000-filament cap; bounded full-wave single-mesh smoke; scheduled explicit three-mesh PEEC/reference and two-mesh/all-column FDTD studies. Establish wall-time baselines on named hardware before setting CI time limits. The lightgun's existing 300-second full-wave allowance is a smoke budget, not a promise of convergence.
- Refusal/interruption preserves partial diagnostics and port completion count. No converged label, usable matrix or derived prediction when required columns/refinement are missing. Progress and cancellation must work during long solves.
