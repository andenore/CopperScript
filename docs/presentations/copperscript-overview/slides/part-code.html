04 / FACTS AND RELATIONSHIPS

Parts hold facts; boards hold intent.

library: part definition (abridged)

part OPAMP_LOW_NOISE {
    pin VP { domains = "power"; … }
    sim opamp { gbw = 18MHz; … }
}

board: component

component C_VP: CAPACITOR {
    value = 100nF; role = decoupling;
    decouples = U1.VP; }

The relationship survives compilation. CopperReview’s generated schematic folds C_VP onto the pin it protects (“C×1” on U1.VP) and lists decouples U1.VP; the same fact informs decoupling placement.

Two layers of information. Library parts hold facts with units: pin domains and directions, ratings where the datasheet gives them, and simulation figures; this example part’s figures are illustrative, as its file says. Board components hold relationships: this capacitor decouples that supply pin. The picture is CopperReview’s schematic of the low-noise preamp example, generated from the compiled IR: the decoupling capacitors are folded onto the supply pins they serve, and selecting C_VP shows the declared relationship. The part excerpt is abridged; the component is the example’s own declaration.
