17 / FINDING THE CAUSE

copper issues names it. copper view shows it.

$ copper issues RUN
fail  19 grouped issue(s)
X1 ESCAPE-CROSSING  SNK/J and SRC/J:
   21 crossing net pairs on one layer;
   move CSI_AN, CSI_AP, … to another layer
C1 CRITICAL-UNROUTED  planned crossing
   is impossible on In2.Cu
$ copper view RUN --issue X1
layers F.Cu · 75 pads, 127 track segments
pad SRC/J.14 CSI_AP @(15.400, 8.175)
pad SNK/J.14 CSI_AP @(52.175, 32.600)
…

Each issue has an id, a cause and a place. The view rings its pads on every copper layer and prints a legend that often answers the question without the picture.

A real failure: a quick four-lane CSI-2 test board between two CopperLib camera connectors, routed with the standard pipeline. copper issues turned the run’s findings into 19 grouped issues, each with an id, a cause and a window. X1 says the two connectors’ pins escape in an order that makes 21 net pairs cross on one layer and names the nets to move; C1 says the planned crossing is impossible on the layers allowed. copper view --issue X1 draws that window per copper layer, rings every pad of the issue and colours each lane, so the escape order of both connectors can be compared at a glance; its legend lists the pads with coordinates. The same commands frame a net, a pad, a component or any window; --filled shows the saved zone fills, placement trials that were rejected show the pose that was kept, and --reference overlays a manufacturer’s layout aligned on the package pads, which is how blocked package exits are compared with the reference design. Output abridged. The fix belongs in placement or the source, and the agent never needs a one-off script to see it.
