08 / PERIPHERAL SELECTION

Choose pins; the compiler checks the mux.

// library: the MCU’s device (excerpt)
peripheral I2C1: i2c {
    signal SDA: open_drain;
    signal SCL: open_drain;
}
mux PB7: I2C1.SDA { selector = "AF6"; }
mux PB6: I2C1.SCL { selector = "AF6"; }

// board: select the peripheral’s pins
configure U1.I2C1 as SENSOR_BUS {
    SDA = PB7;
    SCL = PB6;
}

The choice lowers to the selector, AF6, in the IR. ERC then checks:

  • every required signal is assigned
  • the pin exists on this package and can carry it
  • no pin or peripheral is used twice
  • drive types are electrically compatible
  • shared resources are not set two ways
A device describes the silicon once: its pads, power domains, peripherals and which pads each peripheral signal can use. A package part bonds its pins to those pads. On the board, configure picks the pins for one peripheral; it does not connect anything, nets still do that. The compiler lowers the choice to the concrete alternate-function selector and reports a missing signal, an impossible mux, a pin used twice, an electrical mismatch or a conflicting shared resource. Modes that firmware switches at run time are declared as firmware_managed.
