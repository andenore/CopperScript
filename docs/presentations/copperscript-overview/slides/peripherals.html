08 / PERIPHERAL SELECTION

Choose pins; the compiler checks the mux.

// library: the MCU’s device (excerpt)
peripheral I2C2: i2c {
    signal SDA: open_drain;
    signal SCL: open_drain;
}
mux PA6: I2C2.SDA { selector = "AF8"; }

// board
configure U_MCU.I2C2 as MOTION_I2C {
    SDA = PA6; SCL = PA7;
}

ERC checks required signals, the package’s pins, double use, drive types and shared resources.

CopperReview’s bus view of the full-vertical example, generated from its IR.

A device describes the silicon once: pads, power domains, peripherals and which pads each signal can use. On the board, configure picks the pins for one peripheral; nets still make the connections. The picture is CopperReview’s bus view of the full-vertical example, whose MCU configures seven peripherals: each is a named bus, and MOTION_I2C shows its SCL on PA7 and SDA on PA6, with the datasheets the facts came from. The code is abridged; the pin assignment matches that example. ERC reports a missing signal, an impossible mux, a pin used twice, an electrical mismatch or a conflicting shared resource.
