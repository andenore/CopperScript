09 / MODULES AND POWER STATES

Reusable circuits with typed boundaries.

module Supply3V3 {
    port VIN: power_in;
    port VOUT: power_out;
    port GND: power_in;
    component U1: REGULATOR_3V3;
    net VOUT { port.VOUT; U1.OUT; }
    // … VIN and GND likewise
}

// board
module PWR: power.Supply3V3;
net V3V3 { PWR.VOUT; }
power_state STANDBY { VBUS = on; V3V3 = off; }

Typed ports

Every port sits on exactly one internal net, and the parent must connect it.

Simulated on its own

A bench can target a module and stand in for the board around it.

Power states

copper power-check warns when a powered rail could feed an unpowered one.

Modules package a circuit with typed ports and are imported by URL like parts. Their internal names are kept in the IR, and board constraints can still reach inside, for example fixed_placement(PWR/U1). The soil impedance analyzer example simulates its analog front end as a module, with seventeen benches. Named power states list which rails are on, and power-check analyses each scenario, including possible back-power into an unpowered domain.
