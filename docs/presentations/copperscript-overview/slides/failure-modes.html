21 / WHERE AGENTS GO WRONG

Each common mistake meets a check.

The agent…What catches it in CopperScript
invents a pin, footprint or ratingParts come from pinned libraries with cited sources; unknown facts stay unresolved
connects the right nets with the wrong intentRoles and relationships compile; ERC checks ratings, rails, buses and open pins
cannot see the layout it producedcopper issues and copper view: located causes, legends and pictures
takes “it compiles” for “it works”Every report says what it did not check; screening is never a pass
patches one board instead of the methodClear ownership; routing fixes go into generic algorithms, checked against reference layouts
loses track of what changedThe lock and run.json hash every input and output; stale results are refused
This is the goal of the project in one table: improve an LLM’s ability to produce a good board by closing off the ways it typically goes wrong. Language models invent plausible part data, so parts come from pinned libraries with cited sources and missing facts stay visible. They connect the right nets but ignore why, so intent such as decoupling targets and pin roles is part of the source and checked. They cannot look at a layout, so issues and views give them located causes, text legends and pictures. They over-trust a clean result, so every report names its limits. They patch symptoms, so the project’s rules send fixes into generic algorithms compared with manufacturer reference layouts. And they lose track of state, so every input and output is hashed and old evidence is refused.
