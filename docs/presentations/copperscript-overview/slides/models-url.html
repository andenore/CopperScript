12 / VENDOR MODELS

Vendor models by URL, checked by hash.

part OPA810_VENDOR {
    sim spice {
        source = "https://www.ti.com/lit/zip/SBOMB73";
        sha256 = "bee7ec13…905c4a0a0";
        member = "opa810_a.lib";
        subckt = "OPA810"; dialect = pspice;
    }
}

part Widget {
    model = "https://vendor.example/models/Widget.step";
    model_sha256 = "…";
    model_redistributable = false;
}

SPICE and 3D models stay on the vendor’s site and under the vendor’s terms.

  • copper models fetch downloads them once into the project cache
  • Builds never download; a changed file fails its hash
  • Nothing is shipped unless the part says it may be
  • copper sim --check-model compares a vendor model with the built-in one
The first part is the repository’s OPA810 example: TI’s PSpice model archive pinned by URL and SHA-256, with the file and subcircuit inside it named. The second shows the 3D model fields from the 3D models guide, abridged. Vendor files are often licensed for your own designs but not for redistribution, so the compiler fetches them only on request, checks every byte against the declared hash, and keeps them out of exports unless the part marks them redistributable. The simulator can run the vendor model or the built-in macro model and compare the two.
